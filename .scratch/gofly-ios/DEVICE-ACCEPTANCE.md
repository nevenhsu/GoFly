## 票 03：最終手機驗收步驟草案

1. 完成首次流程後直接選有效座標，未先按 Start 即按 Go：應自動完成私有準備與服務準備，再只執行該快照一次。名稱搜尋不選定前不得出現首結果的候選 Pin。
2. 用名稱、座標與地圖點選切換候選；僅選取／拖圖／開詳情不移動兩個接收 App 的位置。輸入超界座標，保留最後有效候選但停用 Go；有效修正或明確選取才恢復。
3. 鍵盤開關、長結果面板及大字級下檢查 Pin 仍在可見地圖中央，Go 在 Pin 上方且可點；詳情與 Go 分別操作，圖示下方沒有文字。
4. Go 成功後比較兩個接收 App 的實際位置；只出現原候選的模擬箭頭、移除原 Pin／Go。準備期間瀏覽新候選時，新候選及其鏡頭保留，原快照仍是此次命令目的地；一般 GPS 更新不得搶走候選鏡頭，明確回中仍可查看目前位置。
5. 中斷 LocalDevVPN 測試準備失敗可重試，送點回覆不明時不得自動重送、所有 Go 鎖住；有效 GPS 出現也不得解除命令鎖。明確 Stop 完成後才能建立新操作。
6. 成功或回覆不明後 Stop／Restore：clear 實際確認與有效 GPS 分開，等待時保留最後箭頭半透明，新的有效 GPS 更新後才恢復實心。票 03 改進 clear 協定判斷，需重跑此項，票 01 build 3 的歷史通過不能替代新 native 的真機結果。

上述為待驗步驟，尚未執行，不要求開發期間接手機。

## 票 04：最終手機驗收步驟草案

1. 關閉 LocalDevVPN 後明確啟動或 Go；應顯示同一來源的準備及最多三次嘗試，三次後停下、保留原候選／草稿與具體原因。修復 VPN 後由使用者明確重試；Start 不移動位置。
2. 準備中取消新要求：不執行該次位置命令、不清除原候選或草稿；底層尚未返回時不得與新要求重疊。準備取消和設定 Stop 分開，Stop 另會終止現有任務並要求 clear。
3. 在已實作的健康漫步／搖桿任務中，切到可瀏覽的其他模式並提出新要求：準備期間舊任務仍維持運作／暫停；成功交接時舊任務先終止送點，新任務再開始，不能輪流被兩個來源拉動。路線進行／暫停沒有模式入口，不為本項新增隱藏入口。
4. 中斷通道後不得仍顯示舊任務健康運作；恢復通道不復活被交接／停止的舊任務。新命令若位置待確認，保留候選、可開 Pin 詳情與收藏，Go 停用；返回地圖不解鎖，也不新增沒有實際查詢能力的核對按鈕。
5. 明確 Stop 後以新操作重試；比對兩個接收 App、確認沒有遲到舊命令或舊任務復活。送點後的回覆不明不得套用三次準備重試；重現不了未知回覆時如實記未驗，不推定通過。

以上待最終整合 build 交由使用者測試；準備嘗試次數、取消／派送競態與遲到 ACK 另由離線故障注入檢查，不要求現在連接手機。

## 票 05：最終手機驗收步驟草案

1. 搜尋／有效座標的卡片點星號後立即收藏；候選 Pin、鏡頭與接收 App 位置不因星號改變。選取地點只更新候選，仍需 Go 才改位置。點 Pin 開詳情，名稱／可用地址／精確座標與該次點擊的地點一致。
2. 從「最愛地點」短按另一筆，帶回該筆候選與座標；長按只開標籤編輯，不選點或 Go。關閉 sheet 回原面板；空清單有明確空狀態及搜尋入口。
3. 長按後修改標籤但按取消，原標籤不變；在同一編輯頁移除／重新加入星號立即保存，Cancel 不撤回星號，重新加入使用最後保存標籤。未收藏時 Save 停用；重新收藏後儲存才套用新草稿。
4. 在搜尋、詳情、最愛清單交叉檢查空／實心星號同步；移除只影響目前項目，其他同名異地項目、候選及任務保留。關閉並重開 App，核對最愛與已儲存標籤保留，不重播移動。
5. 若出現 O16 位置待確認，返回地圖後 Go 仍停用，但 Pin 詳情與星號／最愛仍可用；收藏操作不解除未知命令鎖。實際硬體未重現未知狀態時如實記待驗，不能以模擬器錯誤注入當手機通過。

資料損壞、非 regular file、原子寫入前失敗與原檔保護由離線系統測試驗證；此清單不要求使用者破壞手機資料或現在連接手機。最終 build 與硬體結果待整合交付後補記。

## 票 06：最終手機驗收步驟草案

1. 路線選兩個地點；搜尋／最愛選取後按取消不改節點，按確認才回填原節點。星號即時保存，不因取消地點編輯撤回。路線編輯可直接點地圖，Pin 不顯示 Go；精確座標立即填入，取得地名／地址後只補顯示資料。查詢未回前改輸入或選另一點，舊資料不得蓋掉新選擇；確認／取消後不改已提交地點。
2. 手選起點與目的地後規劃不移動，按開始才先移至精確起點，再沿步行路徑前進；接收 App 沒有目前位置到指定起點的附加前段。沒有有效 GPS 時仍能手選兩點。
3. 比對 App ACK 進度與接收 App 實際位置，暫停後位置不繼續更新；繼續保持同路徑及進度，沒有補發暫停期間步數。
4. 運作中取消直接回編輯；暫停取消先確認，返回維持暫停，確認保留最後模擬位置及草稿，不 clear。自然到達只顯示一次短提示，服務仍可用。
5. 準備失敗可重試原路線；Stop 後遲到規劃／回覆不重新開始。未知位置命令停止送點且需明確 Stop，不把模擬器失敗注入算手機通過。
6. 最大字級與鍵盤下，路線選點 Pin／確認及瞬移 Pin／Go／輸入都可操作；短高度狀態 card 可精簡，VoiceOver 仍讀完整來源／狀態，關閉鍵盤還原。實際 GPS／模擬來源及未知狀態變化後重新檢查，不丟來源證據、不使版面反覆震盪。模擬來源變更的真機視覺結果尚待本批手機驗證。


## 票 07：最終手機驗收步驟草案

1. 初始只有有效目前位置節點及新增目的地；新增編輯先取消不留空列，重新新增有效目的地後確認才加入。已有兩點後，新增途經點應插在目的地前，角色與編號正確。沒有有效目前位置時仍可手選所有節點，少於兩點停用開始。
2. 左側把手長按拖曳整列，靠近長清單上／下邊緣自動捲動，放開才套用新順序；中止手勢保持原順序。核對名稱、座標、收藏與節點身分跟同一筆移動；中間點選只編輯、右垃圾桶只刪該筆。
3. 既有地點清除搜尋 query 後取消／確認不當作刪除；專用清空地點後確認才刪除。新非空無效輸入不能覆寫舊值，取消保留；清空後重新選有效地點仍能確認新值。專用清空後輸入無效查詢再清關鍵字，或勾選目前位置再取消勾選，均不可復活舊刪除意圖；須再次專用清空才可確認刪除。刪除起點／終點／中間點都重新派角色；新增上限27筆，刪除後可再新增。
4. 將唯一目前位置節點移到中間或末點，開始仍只凍結按下 Start 當下的有效位置，不在未來抵達時重讀 GPS，不增加第二個目前位置。規劃所有有序路段完成前接收 App 不移動；任一段失敗整條不開始，不執行部分路線。
5. 以 VoiceOver 讀各列角色／地名，操作向上／向下移動及刪除，核對對應穩定節點及首尾角色；實際自訂動作手勢／讀音、拖曳取消與長清單觸控手感由此手機批次補驗，不以 Core mutation 或 UI fixture 假稱已驗。

以上待最後整合 build 由使用者集中驗證；開發期間不要求連接或操作手機。
