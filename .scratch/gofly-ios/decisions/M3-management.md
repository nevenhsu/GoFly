# M3：保留資料的重新簽名與配對修復

狀態：完整設計 v2 已經配置的 Advisor 第2／5輪核准；目前只完成 Core 資料契約。持久化、App 門檻、實際 Mac 流程與介面仍待串接，不能以 codec 通過宣稱已可續簽。手機維持 deferred-by-user，全部軟體完成後集中驗收。

手動及選定裝置成功核對連線後的一次自動續簽，共用同一筆管理操作。獨立 management 交易沿用既有私密操作鎖，與首次安裝、重裝、匯入及備份清理互斥。自動選取事件的消耗與交易建立同次原子提交，重開後只接續原筆；刷新、輪詢或返回頁面不再觸發。

續簽使用同身分的覆蓋更新，實際邊界為已固定版本 InstallationProxy 的 `Upgrade`，不得改走卸載或清資料。配對修復不安裝 App。正式首次安裝仍只限 USB，且拒絕覆蓋既有 App。原簽名身分、裝置、配對、本機資料及到期證據各自核對；不能從同名 App、最晚到期 profile 或畫面示意推定身分。

運行中的來源須由 App 核對正常地圖、編輯／實體工作、停止及 clear 狀態，取得全部 owner 鎖後才寫入原筆來源回報。不得暗中 Stop、clear、儲存或關閉編輯。來源已關閉／簽名過期時，Mac 須實際確認同機程序不存在、安裝身分及原正式準備資料；程序不存在不代表 GPS 已恢復。結果未知時不盲目重送。

新簽名會改變精確 App 身分，因此需要新的正式準備回報與明確前後繼承關係。已完成 M2 的目前可編輯資料、Session 與偏好保留；不得重跑原匯入或舊 seed。尚未完成的 M2 不允許中途更新。後續再次續簽需驗證完整且有界的前後關係，不能只憑同 Team 跳過身分。

USB／Wi-Fi 的初始選取不可改寫。中斷後，使用者新選同機通道時先唯讀核對原筆不確定寫入；只有精確回報已消除所有未知，才可原子新增連線版本供下一階段寫入。查詢／自動重連不得偷偷改變原寫入通道或重送。

Core 第一分段新增 `ManagementRequest`、保留實際原始位元組及摘要的 `ManagementInput`、`ManagementSourceReceipt` 與嚴格 codec。請求綁定原 App／準備交易、目標 App／準備交易、裝置、Team、原啟動資料摘要及已完成還原根摘要。修復的目標 App 必須與來源相同。來源回報綁定原始請求摘要及當前 PID；值型別與格式驗證本身沒有安裝、native、GPS 或 owner 准入權限。請求上限32 KiB、回報64 KiB，UUID／摘要採固定格式，未知／重複欄位及非整數版本拒收。

主要驗收流程：已核對連線只自動續簽一次；手動入口共用原筆進度；更新後保留資料且顯示實際到期資訊；配對修復不重裝；中斷保留原筆並核對後續行；M2 已完成資料不重播覆寫。這些完整流程仍待實作及最後手機驗收，現有四項純資料契約檢查只證明該分段。
