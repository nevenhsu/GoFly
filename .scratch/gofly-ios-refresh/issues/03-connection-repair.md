# 03: 三模式自動 reset tunnel、重建 session 並續行原任務

**Status:** implemented; software-verified

**Blocked by:** 01：建立三模式共用狀態投影與刷新基準。五態與恢復結果可直接由共用投影呈現；02 的探測降頻不阻擋本票。

**What to build:** 有效任務執行中斷線後，三模式共用核心協調主動 reset tunnel、重建 session，重新確認位置並接續原任務，無須使用者重新開始。

- [ ] 已知斷線重試期間持續顯示紅色「錯誤」；成功後，斷線前仍在執行且未被使用者暫停／停止的有效任務自動續行，重新取得定位 ACK 後顯示綠色「模擬中」。
- [ ] 共用恢復判斷區分使用者暫停與連線造成的中斷，保留原任務參數及最後確認進度；固定定位續行同一座標，路線續行原路線與方向，漫步續行原任務與目標，搖桿不得重播斷線前已釋放的手勢。
- [ ] 確認斷線立即觸發核心恢復協調，探測成功不能跳過必要 reset／session 重建，不由 View 或 pill 更新送點；每個任務最多一個恢復流程。使用者在斷線／重試中暫停或停止須立即取消自動續行意圖；沿用既有暫停／停止與取消機制，避免正常使用者操作後仍自動續行，不新增重複防禦狀態。
- [ ] 尚未開始、已暫停、已停止、已完成／取消或執行資格已撤銷者不自動續行；冷啟動歷史快照不視為正在運行。失效的背景 grant 不可因重連成功自行恢復，維持既有系統資格規則。
- [ ] 確認故障立即觸發修復；正常 probe pending、不相關錯誤或沒有執行中任務時不觸發自動 reset。
- [ ] 同時收到 probe／送點故障僅產生一個修復流程；既有 native 呼叫未收束時不可重疊 reset／prepare／送點。手動與自動 reset 共享唯一 physical reset 邊界。
- [ ] 區分恢復內部停用與使用者 Stop；維持原 logical task、最後確認座標／路程、方向／目標與速度，session／lease 更新僅經權威交接，不重播舊未確認操作。
- [ ] 驗證正常可達的斷線自動恢復、服務修復失敗／逾時、修復中使用者暫停／停止與正常前後景切換；不做每階段全組合故障注入或偽造內部狀態。
- [ ] 一次斷線的 reset 次數有明確上限與重試策略；建議預設一輪完整自動修復，5 秒 probe 不會重置預算或反覆 reset。正常恢復後的新斷線另計事件。
- [ ] 修復全程維持紅色「錯誤」；有效原任務重建、位置 ACK 成功才回綠色「模擬中」。使用者取消續行後依真實連線及任務階段顯示，不假稱有 session。
