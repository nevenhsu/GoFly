# 06: 完成三模式整合回歸與集中實機驗收

**Status:** software-complete; device-verification-pending

**Blocked by:** 02、03、04、05。

**What to build:** 證明三模式套用同一規則後，畫面穩定、故障及位置可信度仍正確，區分軟體驗證與手機實測結果。

- [ ] 自動回歸按三模式正常 UI 流程覆蓋五態、5 秒 probe、送點／補間、斷線自動修復及使用者暫停／停止；另驗正常 GPS clear、mode 與前後景切換。案例直接覆蓋已變更行為，不窮舉內部狀態組合。
- [ ] 按正常操作先暫停路線／漫步再切換模式，原任務保持暫停；切回原模式也不自行續行，須由使用者繼續。不測執行中直接切換的不可達交錯。
- [ ] 完成相關核心測試、UI 接線驗證、必要模擬器／device unsigned build 及專案必需檢查；各票測試隨票交付，不拖到本票才補。
- [ ] 實機三模式各至少 60 秒，涵蓋多次自動探測及正常送點，錄影對齊狀態證據；pill 不因正常探測／送點跳動，五態文案與色彩正確、箭頭不週期性變淡、無可觀察整頁閃爍。
- [ ] 實機另驗三模式在執行中斷線後確實依序 reset tunnel、重建 session、重新確認位置並自動續行，以及使用者暫停／停止、重試中暫停／停止及正常暫停後切換模式時不自動續行；核對原任務位置、方向與進度不重置、不重複計數。
- [ ] 路線及漫步以正常、延遲與連續 ACK 錄影確認補間無跳回、無切角、無週期性卡頓；故障／停止能立即終止舊動畫；另驗 GPS 恢復。
- [ ] 安裝另依既有授權與正式測試安裝流程；無手機或尚未授權時記 device-verification-pending，軟體完成與實機通過分開。

實作及測試證據：`work/gofly-ios/flicker-optimization/RESULT.md`。最終文案／泛用錯誤定義依目前 `docs/IOS-UI-DESIGN.md` 與 `docs/IOS-STATUS-ERRORS.md`，取代票內較早連線專用用詞。手機／Figma待同步項不宣稱完成。
