## Gemini 方案的修正結論

1. 道路漫步、手動 Go 瞬移、漫步確認改道及十分鐘距離選點方向可採用；按下動作才提交。
2. 不採用其 E1 Toggle、E2 預設僅收合控制、藍色路線、60 pt 頂卡、頂卡更換鈕及 E3 新文案區，這些與本輪渲染不同。
3. 「進入即模擬中」是成功後的目標體驗；必須先有真實定位 ACK。warmup、歷史座標、規劃成功都不能單獨變成綠色 Running 或有效 SimArrow。正常 pending 不增第六種 pill。
4. Reverse geocoding 取得地址不代表找到可通行道路。以共用道路規劃結果及有效幾何為可行判準；不承諾指定速度就能找到單車／機車／高速公路專屬路網。
5. D = V × 600 秒，25 km/h 約4.17 km，是選點距離預算，不保證道路恰好走10分鐘；頂卡剩餘距離／時間必須按實際道路長度及目前速度計算。不加 Gemini 未經確認的±60°偏好或分檔道路限制。

## 已確認的行為契約

### 共用元件與命令

- 手動搖桿 Pin Go 與瞬移模式共用候選驗證、裝置準備、瞬移命令、ACK／錯誤處理與地點卡；瞬移成功後留在搖桿。不能直接套用會持續搶送的固定位置維持，與手動／漫步共用同一 writer。
- 道路漫步與路線模式共用現有 `FallbackRoutePlanner`、`RoutePathProviding`、`PlannedRoute`、路程取樣／方位／進度計算，以及地圖 overlay 與箭頭補間。共用計算與呈現 seam，不同時啟動兩個 execution controller。
- 速度pill、設定移動速度sheet、快選／slider、提交行為及持久化偏好與路線共用同一模組；各畫面只傳入當前速度及可操作狀態，不另製搖桿版本。
- 交通模式順序沿用汽車 → 行人 → 公共交通；最後一項沿用現有失敗處理，不保證有公共交通幾何。不可用直線作失敗 fallback。
- 規劃與執行分開；路線 mode 的 Retry 仍只重取相同輸入的預覽。漫步 Retry 是使用者指定的起點解析、重新選終點與規劃並成功後自動開始，兩者共用底層 planner，不共用錯誤 CTA 語意。
- 保留唯一 ServiceController／FIFO／PointDispatchGate／movement lease，位置與進度只由 ACK 提交；停止或取消後，舊規劃結果不能啟動任務。沿用現有 Task 取消與 revision，不另建通用競態框架。

### 起點與自動啟動

有有效執行中模擬位置時沿用；否則以目前可用位置或最後模擬位置作規劃種子。歷史位置須重新確認才能執行；不能因取到歷史資料復活已暫停任務。進入 E1 的自動定位是新規格，現有 selectMode 只有 warmup，並未完成。

使用者確認：沒有目前位置或最後模擬位置也能開始漫步。流程為「自動選起點 → 用速度計算 D → 自動選目的地 → 兩點取得有效道路 → 確認起點定位 → 自動沿道路漫步」。不要求先手動選 Pin 或允許 GPS。

起點地理範圍未由使用者指定；建議採目前地圖視野中心周邊，找到可規劃的道路起點，避免無提示跨國隨機。這是本方案待確認的預設。每輪候選搜尋必須有界，建議最多3組起訖配對、每組沿用 planner 的交通 fallback，輪次失敗即 Toast，不無限重試。

自動建立起點與手動 Go 共用瞬移提交。先取得完整有效道路才送起點，避免規劃失敗先改變裝置位置。起點使用規劃器實際道路入口，不把 POI 中心硬插入路徑。

### 改道、接管及續航

- E4 確認：以當前模擬位置規劃到候選目的地，成功才替換；不能瞬移到終點。建議重規劃時暫停於最後 ACK，避免使用過期起點。若道路入口不連續，不跳接、不直線補接，視為無法規劃。
- E2 更換地點：保留當前起點，重新自動選目的地並規劃；與 E4 共用替換路線流程。
- 手動接管：拖曳時停自動路徑取樣、保留目的地；放開後從實際確認位置重新規劃到原目的地，成功才繼續。失敗同樣出現規劃 Toast。不能跳回舊折線，也不因放開換隨機目的地。
- 終點 ACK 後以實際道路終點作下一段起點，按最新速度計算 D 選目的地，規劃成功接續。若下一段選點或規劃失敗，保留該終點ACK座標作起點，自動重新選終點並重試一次（首次嘗試加一次重試，最多兩次）；成功即繼續，仍失敗才顯示「無法規劃路線／重試」。規劃等待時停留原點、保持漫步意圖，不使用直線fallback；自動重試次數以每次續航換段為單位，不因失敗重設而無限循環。重規劃不能重置12小時背景工作上限。

### 規劃失敗與重試

選點失敗、道路全部失敗或幾何無效（續航換段先依上述規則自動重選終點重試一次），統一頂部 error Toast「無法規劃路線」，按鈕「重試」；不退回直線、不宣稱仍在前進、不清除最後已確認位置。狀態 pill 依共用 Error 規則，不能把規劃失敗偽稱連線中斷。

使用者最新確認的 Retry 語意：先解析起點，依序採用目前有效且已確認的模擬位置、目前可用位置；只要其中一者可用，就沿用該點而不自動另選起點。兩者都沒有，才自動選起點。之後重新計算 D → 重新自動選目的地 → 重新取得道路 → 必要的起點定位 ACK → 自動漫步。終點必須重新選取，不重送舊失敗配對；起點則不必每次換。只有歷史紀錄、但沒有目前有效位置時，不把歷史當成目前已確認模擬位置。新道路尚未成功前不先瞬移；失敗維持 Toast，可再試。

背景／連線中斷的 E5 恢復則接續原任務與進度，不隨機換點；使用者暫停、結束或背景資格失效優先於自動恢復。兩種 Retry 要有不同原因與處理入口。

## 狀態與驗收

內部階段：手動 → 選起點／目的地 → 規劃中 → 起點確認中 → 道路漫步 → 到站規劃下一段。規劃失敗進 error 等待重試；手動接管／暫停／中斷保留目的地。內部階段不新增共用 pill 狀態。

每張票須有該切片可獨立演示的驗收，不把測試全留到最後。核心案例：無 GPS／無歷史一鍵開始、Retry 有目前模擬位置／只有目前位置／兩者皆無的起點解析分支、手動 Go 不切 tab、E4 兩個確認等價、接管後重新接路、終點 ACK 才換段、改速影響當段速度與下一段預算、取消後過期規劃不得復活。異常只覆蓋真實變更，不增加執行中跨模式搶占矩陣。

軟體實作時執行既有 Core 與 native boundary checks、iOS 模擬器建置，依受影響畫面檢視淺深色／輔助字級／觸控範圍。裝置定位、背景與外部地圖接收另外驗證；安裝必須依正式安裝腳本及既有裝置授權。本輪只有文件與讀取設計，不執行 App 測試或安裝。
