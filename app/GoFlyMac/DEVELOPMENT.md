## 2026-10-18 安裝實機修正與驗收界線

- USB 裝置識別仍正規化核對，連線須保留實際枚舉序號的大小寫；配對檔須接受固定依賴實際回傳的文字或二進位 remote unlock 欄位。私鑰、公鑰、裝置身分及真正 pair-verify 的要求不變。
- iOS 26／27 程序控制使用同機 RSD；保留不自動配對、不回退另一配對來源、不接管既有程序與只停止原交易 PID 的限制。手機 GoFly 已開啟時以 `app-running` 提示關閉 App、保持解鎖並繼續原交易，保留已完成項目，不強制關閉或重裝。
- Apple BuildManifest 的 4 MiB 讀取上限、支援檔案的 4 GiB 總量上限與 256 KiB 交易 JSON 上限分開。固定本機 Xcode 支援來源存在時先經原有封閉清單、私密副本與雜湊驗證；缺少才走下載來源。Cryptex 精確版本核對讀取 payload 的 `CFBundleVersion`，不能拿 BuildManifest 的佔位 `Cryptex1,Version` 代替。
- iOS 首次啟動遇到不存在的 transfer namespace 時可保持空白；任何既有項目仍走完整 no-follow 與檔案型態／權限檢查，不能將此缺少狀態推定為已完成資料還原。

本次 build 22 已取得安裝、配對匯入、支援觀察與 App activation receipt 全部確認，並顯示正常 Welcome；使用者接手拔 USB 測試。這些是實際 producer／手機證據，並非全部定位、背景、iOS 26、資料還原或 Mac GUI 已驗收。過程中的失敗交易與備份均保留；人工核准的封存／替換不宣稱為產品自動復原能力。

## 當前實作範圍與驗收狀態

M1 只處理明確選取 USB 裝置的正式 `com.neven.gofly` 首次安裝。安裝前先唯讀檢查，使用者開始後才建立本次配對、建置／驗簽、安裝及準備必要支援；簽署資料更新需本次選項明確勾選。實際安裝結果、本次 iOS 配對匯入與新觀察的裝置支援三者共同決定 U18，不新增 U19。結果不明不重送、不接管任意既有 App、不以快取或檔案存在宣告裝置已準備。

iOS 在正式交接資料有效並原子提交前不建立正常服務及任務；提交結果不代表 VPN、有效 GPS、clear 或移動授權。Mac 的原交易紀錄與明確續行保留固定裝置和選項。取消等實際程序返回；現有 GoFly 不以首次安裝覆蓋。M2＋17 的 USB 同機重裝、iOS 匯出／還原及本機備份管理已接入正式介面並完成主要離線流程檢查，實機仍待驗；自動／手動續簽與配對修復已接入獨立管理記錄、執行器及頁面，完成離線檢查；實際更新與修復仍待集中手機驗收。Wi-Fi 同機重裝／匯入及可攜 DMG 尚未交付。

本機備份以原 M2 完整交易與封包為依據，不以清單檔案推定匯入成功。首次維護確認成功後開始七天保留；未完成匯入永不自動刪除。提前刪除需原筆確認，只刪 Mac 副本；與其他寫入共用操作鎖。中斷時保留持久刪除意圖，先清 payload，最後才刪 manifest。無 manifest 的未完成備份只顯示保留狀態，不掃描或猜測資料數量。待匯入入口只回到原交易，由使用者核對原手機後續行。這些是軟體行為，未代表手機匯入驗收完成。

下列 2026-10-17 線框要求保留為產品規格；其中「本輪只更新 wireframe」等句子描述當日設計工作，不代表目前程式現況。各項最終實作及驗收以 [M1 票](../../.scratch/gofly-ios/issues/M1-first-install.md)、正式後續票與[集中手機驗收](../../.scratch/gofly-ios/DEVICE-ACCEPTANCE.md)為準。開發期間不要求接手機，所有硬體項目保持未驗。

## 重裝命令的 iOS 前景接收

Mac 將匯出、封存及釋放命令寫入既有固定信箱；iOS 在前景以同一序列入口接收管理與重裝命令，網址入口保留。接收前沿用既有固定信箱封存，接受 AFC 交付的目錄／檔案權限並轉為私密；僅四個既有 producer 輸入檔可用此規則，App 自有收據與資料仍維持嚴格權限。每筆重裝命令綁定原始請求與控制檔的完整位元組、識別及請求雜湊；排隊後及回報前再次核對，檔案被替換時不替新命令寫入舊結果。只有相符且沒有錯誤的持久化完成回報才抑制重複執行，忙碌或寫入失敗保持可重試。

管理鎖定期間不准入重裝；實際匯出仍在 preparing／ready／removalSealed 時不准入管理。兩類信箱獨立讀取並交替派發，歷史管理命令只在同一識別與請求雜湊的實際 adopted／released 狀態下略過。進入背景會作廢尚未准入的觀察命令；已開始的工作仍持有原本資料鎖直到完成。這不增加背景執行能力，也不代表 Wi-Fi、原程序身分、定位清除或實機交接已通過。

## 重裝來源與新目標的身分

來源匯出核對目前來源 App 的 Bundle／build，並將其實際完整身分保存在來源收據與封包。新目標可能有不同的 build、簽署描述檔與執行檔雜湊；這個身分固定在原始請求與 manifest 中，交由新安裝的還原流程核對，不能要求它等於舊來源。來源／目標與裝置、交易、nonce、原始請求及完整封包的綁定均保留。

Mac 收到的匯出回報即使顯示 ready／preparing，只要帶有錯誤，就保持待確認，不授予來源 PID、備份或移除權限。取消時用於改送完整釋放命令的 ready＋export-conflict 仍只是觀察資料，不能當成釋放成功。以上不改變實際資料鎖、原生停止／清除或新目標還原的完成門檻。

## 安裝完成條件與自動裝置準備

2026-10-17 使用者確認：不要讓 iOS 在安裝後另外下載支援資料，也不需要 U19「在 iPhone 完成最後設定」。Mac 安裝流程自動處理真正必要的裝置準備，完成後才交接；無實際需要時略過，不為舊稿 H12 製造額外步驟。

已核對現有實作：[DeveloperDiskImageService](../LocalGo/StikDebug/Services/DeveloperDiskImageService.swift) 確有 DDI 檔案下載與格式選擇；[LiveLocationEngine](../LocalGo/StikDebug/LocalGo/LiveLocationEngine.swift) 及 [DevicePreparationPolicy](../LocalGo/StikDebug/LocalGo/DevicePreparationPolicy.swift) 會先看裝置已掛載狀態，已就緒則重用，否則依需要使用支援檔。這是自動處理的必要技術資料，不是使用者必須額外設定的內容。現有手機 prepare 仍負責下載；移至 Mac 是待實作變更，不代表目前 GUI／CLI 已完成。

- Mac 在同一安裝交易中，核對選定 iPhone 與 iOS 版本，依實際需要取得、交付及準備支援項目；已就緒的重用或略過。進度只顯示「準備裝置」，不新增資料設定頁、額外確認或獨立完成頁。
- App 部署、配對匯入及本次必要裝置準備均驗證完成，才顯示 U18「安裝完成」。僅 App 已安裝、下載完成、檔案存在或配對回報，均不能單獨代表整體準備成功；實際裝置結果須可確認。
- 裝置準備失敗或中斷，使用 Mac 共用安裝失敗模板，顯示具體原因並保留已完成項目，只重試未完成部分；不能假稱完成、重做已成功部署或交給 iOS H12 補下載。無法確認已執行結果時先核對同一裝置，不盲目重送。
- 安裝完成後即可拔除 USB；Mac 不再顯示 U19、查看手機設定流程或要求手機補裝資料。iPhone 開啟 GoFly 沿用 01 首次流程，VPN 通道仍必要、GPS／背景選用，不因 Mac 成功而宣告 VPN 已連線、GPS 已取得或已開始模擬。
- iOS 重啟後可重新建立服務／掛載既有資料；這與重新下載或手動資料設定不同。iOS 更新、缺少或不相容時，顯示既有裝置處理入口並回 Mac 裝置管理更新準備，不加回獨立下載頁。此路徑仍需實機驗證。
- 重新安裝也須符合必要裝置準備與既有資料匯入完成條件；重新簽名仍沿用既有保留資料規則，不因本要求改成移除／重裝。首次安裝 USB 限制維持。

驗收：必要資料缺少時 Mac 自動準備；已備妥時不重複下載／設定；下載成功但裝置驗證失敗仍未完成；中斷後只接續未完成項目；iOS 不出現 H12 或手動資料設定；Mac 不出現 U19，U18 可結束；拔 USB 後開啟 GoFly 不需首次補下載；iOS 版本變更與重啟須驗證既有資料可用或由 Mac 修復。保留原來簽名、配對、安裝與資料驗收，不能用畫面／假回報代替實機結果。

## 連線成功後自動重新簽名

在 Mac App「裝置管理」中，使用者選擇裝置，並成功建立及核對該裝置連線後，**自動開始為所選裝置的 GoFly App 重新簽名**。USB 與 Wi-Fi 均適用；不要求使用者再點一次重新簽名，也不以簽名已到期或即將到期為觸發條件。僅在清單看到裝置、點選但未連上、連線失敗或裝置身分尚未確認時，不觸發。

主流程：

1. 進入裝置管理，選擇目前可連接的裝置。
2. 依選定的 USB／Wi-Fi 通道連線，核對裝置身分。
3. 連線成功後，自動開始既有重新簽名前置檢查與簽名流程，顯示進度。
4. 完成後更新同一裝置的簽名結果及可驗證的到期日，留在裝置管理；失敗則顯示原因，保留該裝置及重試入口。

「連線成功」與「重新簽名完成」是兩個狀態，不能在連上時就顯示簽名成功。簽名到期後 iOS App 無法使用；自動流程是 Mac 端更新，不是 iOS 自動續簽。手機 C06 的 Mac App → 裝置管理說明與此對應。

## 保留手動重新簽名流程

現有「簽名與重新簽名」入口、手動開始、進度、完成與失敗處理流程全部保留。使用者仍可主動進入該流程再次重新簽名；自動簽名失敗後也可由此修正條件並重試。

自動與手動入口執行同一重新簽名操作，沿用所選裝置、相容簽名身分及資料保留規則，不各自維護兩套結果。自動流程執行中，手動入口顯示同一筆進度並防止重複送出。目前手動入口已接入 protocol5 管理執行器；本機預檢與原筆接續檢查通過，實際手機更新／配對結果仍須最後集中驗收。

## 觸發、資料與中斷規則

- 每筆由使用者明確選定裝置並成功連線的交易，最多觸發一次自動重新簽名；同一事件重送、裝置列表刷新、狀態輪詢或返回裝置頁不重複觸發。之後使用者重新選定並建立新連線，可開始新一筆交易。
- 相同裝置只列一次，預設 USB；同時觀察到 USB／Wi-Fi 時提供明確通道選擇。唯讀檢查也固定選定通道，不以 USB 優先偷偷改寫使用者選擇。已開始操作的換線須經原筆唯讀核對及持久化新連線版本，不額外啟動另一筆簽名。首次安裝仍只列 USB。
- 自動流程沿用手動重新簽名的前置條件。缺少簽名身分、需要登入／系統確認或需先停止並清除手機模擬定位時，呈現待處理原因及既有處理路徑；不能忽略前置條件、假稱完成或默默終止手機任務。
- 保留既有 App 資料與設定、最愛、標籤、路線及配對。重新簽名不等於重新安裝，不自動改走卸載、全新安裝或清除資料；簽名不相容時顯示原因，依既有人工流程處理。
- 同一裝置一次只執行一筆簽名交易，與安裝、重裝、匯入及其他裝置寫入互斥。失敗不無限自動重試；可由使用者透過既有手動流程重試。
- 中斷、取消或切換裝置時，作廢舊選取的後續結果，不能將結果套到另一支手機。簽名部署／寫入中通道中斷，沿用先暫停、重新核對同機，再由使用者繼續的規則；不因 Wi-Fi／USB 自動切換就盲目重送已可能完成的寫入。
- 只有實際簽名／部署結果確認後才顯示完成；有效期依可驗證資料，未知顯示待確認，不使用固定日期。成功更新簽名不代表已恢復 GPS 或已啟動模擬。

## 開發驗收條件

| 情境 | 預期結果 |
| --- | --- |
| 裝置管理選 USB 裝置並成功連線 | 自動重新簽名一次，不另要求點手動入口 |
| 裝置管理選 Wi-Fi 裝置並成功連線 | 與 USB 相同行為，目標身分與通道正確 |
| 裝置列出但尚未連線／連線失敗 | 不觸發簽名，顯示連線原因 |
| 同一成功事件重送、刷新／輪詢、同機傳輸切換 | 不新增第二筆簽名交易 |
| 自動簽名進行中點手動入口 | 顯示同一筆進度，不並行寫入 |
| 自動完成後主動執行手動重新簽名 | 既有手動流程仍可用，目標是同一所選裝置 |
| 自動失敗、缺前置條件或簽名不相容 | 不顯示成功、不清資料；可處理原因並透過手動流程重試 |
| 寫入中斷／取消／切換手機 | 不盲目重送、不套用舊裝置結果；核對後按既有流程繼續 |
